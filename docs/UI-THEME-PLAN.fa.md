# برنامهٔ بهبود UI و هماهنگی با تم فعال

تاریخ: ۲۰۲۶-۰۹-۲۶

وضعیت: برنامهٔ اجرایی پیشنهادی؛ قابلیت‌های این سند هنوز پیاده‌سازی نشده‌اند.

مبنای بررسی: سورس Neo-Bpms پس از کامیت `70f8657`؛ بررسی این مرحله ایستا است.

## هدف و دامنه

کاربر با تغییر تم، یک رابط هماهنگ ببیند: رنگ اصلی، زمینه، متن، کادر، سایه،
فوکوس و حالت‌های تعاملی در همهٔ بخش‌ها از تم فعال پیروی کنند. بهبود ظاهر همراه
با خوانایی، نظم فرم‌ها و حفظ فضای مفید جدول‌ها انجام شود. «تم فعال» فقط روشن یا
تیره نیست؛ پالت انتخاب‌شده و تنظیمات ظاهری موجود میزبان نیز باید حفظ شوند.

دامنه شامل MVC و کنترل‌های تولیدشده از مدل، AdminPanel.Core، EditableGrid،
Monitoring، ورود و بازیابی رمز، فرم‌های iframe، منوها، دیالوگ‌ها، کمبو و تقویم، جدول، گزارش، داشبورد،
نمودار، اعلان، خطا، حالت خالی و بارگذاری است. پوستهٔ ابزارهای طراحی BPMN/DMN،
ویرایشگر و نمایشگر فایل نیز در فهرست پوشش قرار می‌گیرد؛ محتوای سند، تصاویر،
لوگوها و رنگ‌های معنایی فرایند نباید خودکار معکوس یا بازنویسی شوند.
چاپ و خروجی گزارش، نمای مخصوص خود با خوانایی روی کاغذ دارند.

## قرارداد پیشنهادی تم

قرارداد نهایی پس از بررسی میزبان تثبیت می‌شود؛ نام‌های زیر پیشنهاد طراحی‌اند، نه API موجود.

- در هر سند، یک وضعیت حل‌شدهٔ تم داشته باشیم. انتخاب فعال میزبان/کاربر مرجع است؛
  تنظیم ذخیره‌شده و پیش‌فرض از مسیر فعلی پروژه خوانده شوند. دنبال‌کردن سیستم‌عامل
  فقط در صورت انتخاب حالت خودکار، اگر چنین حالتی پشتیبانی شود، اعمال شود.
- مصرف‌کننده‌های فعلی `data-theme`، `.dark` و در صورت نیاز
  `data-bs-theme` از همان وضعیت مشترک تغذیه شوند. هیچ کامپوننتی مستقلاً تم انتخاب نکند.
- متغیرهای معنایی برای زمینهٔ صفحه، سطح و سطح شناور، متن اصلی و فرعی، مرز،
  رنگ اصلی و متن روی آن، hover، انتخاب، focus، disabled و وضعیت‌های موفق/هشدار/خطا
  تعریف شود. نام پیشنهادی مانند `--neo-surface` و `--neo-text` است.
- فونت، فاصله، شعاع، ارتفاع کنترل و سایه نیز قرارداد مشترک داشته باشند؛
  جهت متن از زبان و تنظیم معتبر موجود گرفته شود، نه از روشن/تیره بودن.
- Bootstrap، Tailwind و نام‌های CSS فعلی از طریق نگاشت سازگار به این متغیرها وصل شوند.
  ابتدا مصرف‌کننده‌ها مهاجرت کنند و سپس aliasهای واقعاً بلااستفاده حذف شوند.
- تم پیش از نمایش محتوای اولیه اعمال شود؛ بارگذاری مجدد نباید پرش روشن/تیره داشته باشد.
  نبود localStorage، دادهٔ ذخیره‌شدهٔ نامعتبر و اجرای SSR نباید صفحه را خراب کند.
- تغییر تم باید popup باز و محتوای جدید AJAX را نیز به‌روز کند، بدون از دست رفتن
  مقدار فرم، موقعیت جدول، انتخاب ردیف یا وضعیت ویرایش.
- portalهای منتقل‌شده به body باید متغیرها را دریافت کنند. برای iframeهای هم‌مبدأ،
  همگام‌سازی اولیه و تغییر بعدی تعریف شود؛ برای iframe تحت کنترل با مبدأ متفاوت،
  پیام نسخه‌دار با کنترل origin و source لازم است. iframe بیرونیِ فاقد همکاری
  به‌عنوان استثنای مستند ثبت شود؛ ادعای پوشش کامل برای آن نشود.

## بهبودهای UX همراه با هماهنگی تم

- فرم‌ها: ریتم ثابت فاصله و تراز برچسب، گروه‌بندی منطقی، نمایش تدریجی تنظیمات
  پیشرفته و حفظ مقادیر فعال؛ قابلیت‌های موجود ابتدا شناسایی و بازاستفاده شوند.
- فیلترها: همان مدل و مسیر query فعلی حفظ شود. فیلتر سرستون راه دسترسی به همان
  کنترل باشد؛ دکمهٔ اعمال، پاک‌کردن و نشانگر فیلتر فعال رفتار یکنواخت داشته باشند.
- جدول‌ها: خوانایی سطر و سرستون، تمایز انتخاب و hover، جای ثابت عملیات متداول
  و حفظ فضای داده؛ چسباندن هدر فقط بعد از بررسی scroll و popupها.
- دکمه‌ها: یک عملیات اصلی مشخص در هر ناحیه؛ ظاهر ثانویه، مخرب، غیرفعال و درحال
  اجرا قابل تشخیص باشد. آیکون‌های بدون متن نام قابل دسترسی داشته باشند.
- داشبورد: هماهنگی عنوان، واحد، عدد و شرح؛ رنگ هشدار یا خطا معنای ثابتی داشته باشد
  و صرفاً با رنگ بیان نشود. تم نباید معنای سری‌های نمودار را جابه‌جا کند.
- لایه‌های شناور: سلسله‌مراتب مستند برای backdrop، modal و popup داخل modal؛
  stacking context و clipping بررسی شود. افزایش بی‌قاعدهٔ z-index جای این بررسی را نگیرد.
- موبایل و RTL/LTR: فاصله‌های منطقی، دسترسی به عملیات، شکستن متن بلند و
  اندازهٔ مناسب هدف لمسی؛ اسکرول افقی جدولِ عریض در ظرف خود، نه کل صفحه.
- کیبورد: فوکوس قابل مشاهده، حرکت منطقی Tab، Escape برای بستن و برگشت فوکوس
  به بازکننده؛ کاهش حرکت مطابق ترجیح کاربر برای انیمیشن‌های غیرضروری.

## ماتریس پذیرش

صفحهٔ نمونهٔ مشترک، همهٔ حالت‌های پایه را پوشش دهد؛ صفحه‌های واقعی با نمونه‌های
نماینده و بر اساس ریسک انتخاب شوند، نه ضرب کامل همهٔ ترکیب‌ها.

| محور | موارد الزامی |
| --- | --- |
| تم | روشن، تیره و تمام پالت‌های انتخابی موجود؛ انتخاب صریح مخالف تم سیستم؛ حالت خودکار تنها در صورت پشتیبانی |
| زمان | نخستین نمایش، refresh، تعویض تم بدون reload، پنجرهٔ شناور باز، محتوای AJAX و بارگذاری دیرهنگام iframe |
| ورودی | عادی، hover، focus، انتخاب‌شده، readonly، disabled، خطا، loading و empty |
| چیدمان | فارسی RTL و انگلیسی LTR؛ عرض نمونهٔ ۳۹۰، ۷۶۸ و ۱۴۴۰ پیکسل؛ بزرگ‌نمایی مرورگر |
| رفتار | تایپ و ویرایش حفظ‌شده، اعمال و پاک‌کردن فیلتر، sort/paging، انتخاب ردیف، باز و بسته‌شدن popup، تعامل کیبورد |
| ارائه | computed style مطابق توکن، کنتراست اندازه‌گیری‌شده و متن خوانا، عدم بریده‌شدن popup، عدم سرریز صفحه |
| میزبان | پاسخ موفق asset با محتوای درست، ترتیب CSS، نسخه‌گذاری/cache و رفتار بعد از انتشار |
| اسناد | چاپ/خروجی خوانا؛ محتوای فایل و رنگ معنایی نمودار/فرایند حفظ‌شده |

در مرحلهٔ ۱، palette، فونت و دادهٔ نمونهٔ ثابت برای مقایسهٔ تصویر ثبت شود.
در مرحلهٔ ۲، آزمون‌های مرورگر موجود فیلتر اجرا و سناریوی تغییر تم با popup باز
اضافه شود. برای React، نمودار و iframe از ابزار آزمون موجود همان پروژه استفاده
شود و ابزار موازی فقط در صورت نبود پوشش لازم اضافه گردد. آزمون نمونه، جای
تست سامانهٔ احراز هویت‌شده و مسیر واقعی ارسال درخواست را نمی‌گیرد.

## انتشار، ساده‌سازی و نگهداری

هر بسته شامل محدودهٔ مشخص، تصویر قبل/بعد، نتیجهٔ آزمون، موارد خارج از پوشش و
روش بازگشت مستقل باشد. کلاس‌ها و attributeهای مورد استفادهٔ مولد، validator و
handlerها تا زمان بررسی مصرف‌کننده‌ها حفظ شوند. CSS وابسته به vendor در یک
adapter محدود نگهداری شود؛ vendor و فایل‌های dist مستقیماً اصلاح نشوند.

حذف کد تکراری فقط پس از یکسان‌کردن رفتار و پوشش آزمون انجام شود. انتخابگر عمومی
یا جایگزینی سراسری رنگ سفید/مشکی مجاز نیست؛ رنگ محتوای سند، برند و وضعیت داده
با رنگ سطح UI یک معنا ندارد. تغییر ظاهر از تغییر قرارداد API و منطق کسب‌وکار
در کامیت‌های قابل بررسی جدا بماند.

با پیاده‌سازی قرارداد تم، راهنمای توسعهٔ UI و Skill موجود به‌روزرسانی شوند.
افزودن recipe یا ابزار MCP صرفاً در صورت نیاز واقعی انجام شود؛ نام ابزار پیشنهادی
در این برنامه به‌عنوان ابزار موجود معرفی نمی‌شود. تغییر فعلی فقط برنامه و
README است و قرارداد پنج ابزار MCP را تغییر نمی‌دهد. قاعدهٔ
[نگهداری همراهان](COMPANION-MAINTENANCE.md) در تمام مراحل برقرار است.


## وضعیت بستهٔ نخست — ۲۰۲۶-۰۹-۲۶

میزبان اولویت‌دار Hyper است. منشأ پالت در `ThemeService` و partial
`_ThemeVariables.cshtml` میزبان شناسایی شد. زیرساخت مشترک و اتصال
MVC، Monitoring، EditableGrid و AdminPanel در سورس اعمال شده است. آزمون‌های
کنترل‌ها و تم در Edge و ساخت Production سه برنامهٔ React موفق بوده‌اند. این وضعیت به معنی
پایان هیچ‌یک از معیارهای پذیرش دیداری یا انتشار نیست. تصاویر محیط واقعی،
پذیرش محیط واقعی Hyper و تأیید مسیر asset میزبان هنوز جداگانه بررسی می‌شوند.

جزئیات قرارداد، پوشش، محدودیت‌ها و نتیجهٔ بررسی‌ها در
[گزارش پیاده‌سازی](UI-THEME-IMPLEMENTATION.fa.md) ثبت شده‌اند.
