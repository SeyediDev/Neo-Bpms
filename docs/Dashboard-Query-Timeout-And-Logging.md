# مدیریت Timeout و لاگ‌گیری پرس‌وجوهای کند در داشبوردها

## خلاصه

این سیستم برای مدیریت پرس‌وجوهای کند در داشبوردها طراحی شده است. در صورت طولانی شدن پرس‌وجوی یک ویجت، سیستم به صورت خودکار آن را متوقف می‌کند و خطای مناسب را در ویجت نمایش می‌دهد. همچنین، پرس‌وجوهای کند در لاگ ثبت می‌شوند تا ادمین بتواند آن‌ها را بررسی کند.

## ویژگی‌ها

### 1. Timeout خودکار برای ویجت‌ها
- هر ویجت در داشبورد دارای یک timeout قابل تنظیم است
- در صورت طولانی شدن پرس‌وجو، به صورت خودکار متوقف می‌شود
- خطای مناسب در ویجت نمایش داده می‌شود

### 2. لاگ‌گیری پرس‌وجوهای کند
- پرس‌وجوهایی که بیشتر از threshold مشخص شده طول بکشند، در لاگ ثبت می‌شوند
- در حالت Development، جزئیات کامل پرس‌وجو (شامل متن SQL) در لاگ ثبت می‌شود
- در حالت Production، خلاصه‌ای از پرس‌وجوی کند ثبت می‌شود

### 3. نمایش خطا در ویجت
- در صورت timeout یا خطا، پیام مناسب در ویجت نمایش داده می‌شود
- کاربر می‌تواند مشکل را مشاهده کند و با مدیر سیستم تماس بگیرد

## تنظیمات

### تنظیمات پیش‌فرض

تنظیمات پیش‌فرض به صورت خودکار در هنگام راه‌اندازی برنامه ایجاد می‌شوند. در صورت نیاز، می‌توانید آن‌ها را به صورت دستی از طریق SQL Script ایجاد کنید:

```sql
-- اجرای اسکریپت SQL
-- فایل: docs/Dashboard-Settings-SQL-Script.sql
```

### تنظیمات در پنل ادمین

تنظیمات timeout و slow query threshold را می‌توانید از طریق پنل ادمین مدیریت کنید:

1. به منوی **Common** → **Dashboard Settings** بروید
2. تنظیمات زیر را ویرایش کنید:
   - **Dashboard:WidgetTimeoutMs**: زمان timeout برای پرس‌وجوهای ویجت (به میلی‌ثانیه)
   - **Dashboard:SlowQueryThresholdMs**: Threshold برای لاگ‌گیری پرس‌وجوهای کند (به میلی‌ثانیه)

**نکته**: تنظیمات پیش‌فرض به صورت خودکار در هنگام راه‌اندازی برنامه ایجاد می‌شوند. در صورت عدم وجود، می‌توانید آن‌ها را از طریق پنل ادمین یا SQL Script ایجاد کنید.

### افزودن تنظیمات به appsettings.json (اختیاری)

همچنین می‌توانید تنظیمات را در فایل `appsettings.json` یا `appsettings.Development.json` اضافه کنید:

```json
{
  "Dashboard": {
    "WidgetTimeoutMs": 30000,
    "SlowQueryThresholdMs": 5000
  }
}
```

**نکته**: تنظیمات در دیتابیس اولویت دارند. اگر تنظیمات در دیتابیس وجود داشته باشد، از آن استفاده می‌شود، در غیر این صورت از appsettings.json استفاده می‌شود.

### توضیح پارامترها

- **WidgetTimeoutMs**: زمان timeout برای پرس‌وجوهای ویجت (به میلی‌ثانیه)
  - پیش‌فرض: 30000 (30 ثانیه)
  - توصیه: برای داشبوردهای با پرس‌وجوهای پیچیده، این مقدار را افزایش دهید

- **SlowQueryThresholdMs**: Threshold برای لاگ‌گیری پرس‌وجوهای کند (به میلی‌ثانیه)
  - پیش‌فرض: 5000 (5 ثانیه)
  - پرس‌وجوهایی که بیشتر از این زمان طول بکشند، در لاگ ثبت می‌شوند

## نحوه استفاده

### در حالت Development

1. تنظیمات را در `appsettings.Development.json` اضافه کنید
2. برنامه را اجرا کنید
3. در صورت کند بودن پرس‌وجو، جزئیات کامل در لاگ ثبت می‌شود

## نمایش خطا در ویجت

در صورت timeout یا خطا، پیام زیر در ویجت نمایش داده می‌شود:

```
مشکلی در نمایش این گزارش رخ داده است.
لطفاً پس از رفع خطا یا با مدیر سیستم تماس بگیرید.

• پرس‌وجو به دلیل طولانی شدن زمان اجرا (بیش از 30 ثانیه) متوقف شد.
  کد: TIMEOUT
```

## بهینه‌سازی پرس‌وجوهای کند

برای بهینه‌سازی پرس‌وجوهای کند، می‌توانید:

1. **ایجاد Index**: برای فیلدهایی که در WHERE استفاده می‌شوند
2. **بهینه‌سازی JOIN**: از JOIN های غیرضروری اجتناب کنید
3. **محدود کردن داده‌ها**: از فیلترهای مناسب استفاده کنید
4. **استفاده از View**: برای پرس‌وجوهای پیچیده، از View استفاده کنید
5. **Caching**: برای داده‌های ثابت، از caching استفاده کنید

## نکات مهم

1. **Timeout**: مقدار timeout را بر اساس پیچیدگی پرس‌وجوها تنظیم کنید
   - برای پرس‌وجوهای ساده: 10-15 ثانیه
   - برای پرس‌وجوهای متوسط: 20-30 ثانیه
   - برای پرس‌وجوهای پیچیده: 60 ثانیه یا بیشتر

2. **SlowQueryThreshold**: این مقدار را بر اساس نیاز تنظیم کنید
   - برای شناسایی پرس‌وجوهای کند: 3-5 ثانیه
   - برای شناسایی پرس‌وجوهای بسیار کند: 10 ثانیه یا بیشتر

3. **لاگ‌گیری**: در حالت Production، لاگ‌گیری کامل را فعال نکنید تا حجم لاگ‌ها زیاد نشود
